# PDAC Multimodal Risk Detection (PancraDX)

Final Year Project: a multimodal machine-learning pipeline for early risk
detection of pancreatic ductal adenocarcinoma (PDAC), combining a CT-imaging
branch and a urinary-biomarker (clinical/tabular) branch behind a
clinician-facing Streamlit dashboard, **PancraDX**.

> **Research/educational project only.** Nothing in this repository is a
> validated diagnostic device, has regulatory clearance, or should inform an
> actual clinical decision.

---

## Overview

Pancreatic cancer has the worst survival rate of any major cancer largely
because it is diagnosed late. This project explores whether two independent,
low-cost signal sources — routine abdominal CT and a urinary biomarker panel
— can each flag early risk on their own, since no dataset here provides both
modalities for the same patient (see [Branch architecture](#branch-architecture)).

| Branch | Task | Data | Model | Headline result |
|---|---|---|---|---|
| **Imaging** | Pancreas segmentation + cancer detection from CT slices | MSD Task07 (281 pts) + NIH Pancreas-CT (80 pts), 90,693 slices | ResNet-50 U-Net (2-head), 5-fold CV | ROC-AUC 0.9934 ± 0.0069, recall 0.9628 ± 0.0372 |
| **Clinical** | PDAC risk from urinary biomarkers | Debernardi et al. 2020 (590 pts, 199 PDAC) | XGBoost, MICE-imputed CA19-9, repeated 5×20 CV | ROC-AUC 0.9077, cohort-out 0.8375, leave-one-site-out 0.8195 |
| **Fusion** | Side-by-side risk view, no joint score (no paired data exists) | — | Rule-based combiner | See `docs/Fusion_documentation.md` |

Full methodology, every design decision, and every verified number are
written up in [`docs/`](docs/) — see the [documentation index](#documentation)
below.

## Branch architecture

No patient in the source data has both a CT scan and a urine sample — MSD,
NIH, and the Debernardi cohort are three separate, unpaired sources. Each
branch is therefore trained and validated **independently**; the fusion
stage combines two already-calibrated, already-independently-validated risk
scores for the dashboard's combined view, and deliberately never reports a
single joint accuracy/AUC across both modalities (there is no ground truth
to score that against). This constraint, and why it isn't a shortcut to work
around, is explained in `docs/Fusion_Evaluation_documentation.md`.

## Repository structure

```
├── dashboard/          # Streamlit app (PancraDX) — Register → Predict → Analytics → Reports → About
├── docs/                # Full technical documentation (see below)
├── notebooks/           # Exploratory data analysis (CT + tabular)
├── src/
│   ├── clinical/         # Tabular cleaning, imputer benchmark, model comparison, final fit, SHAP
│   ├── imaging/          # CT preprocessing, training, evaluation, confound checks
│   ├── fusion/            # Cross-branch comparison + inference-time combiner
│   ├── utils/             # Shared config and metrics
│   └── inference.py       # Loads final artifacts for the dashboard; never retrains
├── outputs/              # Figures (EDA, QA, evaluation) — safe to version, no patient data
├── results/               # Metrics tables (CSV) — safe to version, no patient data
├── requirements.txt        # Top-level dependency floors, grouped and commented
├── requirements-lock.txt    # Full pinned environment (`pip freeze`) for exact reproducibility
├── data/                  # Not tracked (gitignored) — raw + processed datasets, see below
└── checkpoints/            # Not tracked (gitignored) — trained model artifacts
```

`data/` and `checkpoints/` are intentionally excluded from version control:
the raw datasets are large (tens of GB) and third-party licensed (see
`docs/Data_Collection_Summary.md`), and trained artifacts are regenerated by
the pipeline rather than committed. `outputs/` and `results/` — figures and
metrics tables produced *from* that data — are small and safe to version, and
are the source of every number quoted in `docs/`.

## Getting started

**Requirements:** Python 3.13, a CUDA-capable GPU recommended for imaging
training (inference/dashboard run fine on CPU).

```bash
python -m venv fyp_env
fyp_env\Scripts\activate        # Windows
pip install -r requirements.txt
# Install torch/torchvision separately with the CUDA-matched command from
# https://pytorch.org (check `nvidia-smi` for your CUDA version first)
```

`requirements-lock.txt` is the exact, verified environment this project was
built and run against (`pip freeze`) — use it if you want a bit-for-bit match
instead of the floor versions in `requirements.txt`.

Datasets are not included in this repository. See
`docs/Data_Collection_Summary.md` for sources, licenses, and download links
for MSD Task07 Pancreas, NIH Pancreas-CT, PANORAMA, and the Debernardi et al.
urinary biomarker dataset, and `docs/FYP_Folder_Structure_Manual.md` for the
expected `data/` layout.

### Running the dashboard

```bash
streamlit run dashboard/app.py
```

The dashboard only reads already-trained, already-calibrated artifacts from
`checkpoints/{clinical,imaging,fusion}/final/` — it never trains or refits
anything. See `docs/Dashboard_documentation.md` for the full page-by-page
walkthrough.

## Status

The clinical branch is fully validated end-to-end (cleaning → imputation →
model selection → calibrated final fit → SHAP explanations). The imaging
branch is trained, evaluated across 3-fold and 5-fold candidate runs, and
promoted with an explicit Grad-CAM/segmentation-overlap confound check
(MSD and NIH are different institutions/scanners, so this was verified
rather than assumed away). The fusion stage and dashboard are built and
functional. See `docs/FYP_Codebase_Status_Audit.md` for the current,
file-by-file status of every component.
